개발 계획 수립

체계적인 개발을 위한 필수 단계

왜 계획이 필요한가?

명확한 계획 없이 코딩을 시작하면 중간에 막히거나, 불필요한 시행착오를 겪게 됩니다. 체계적인 계획은 효율적인 개발의 첫걸음입니
다.

계획 없이 개발할 때                                                          계획의 이점
      방향 상실 - 무엇을 만들어야 하는지 불명확                                             명확한 방향 - 무엇을 언제까지 만들 것인지 분명
      API 탐색 시간 낭비 - 필요한 API를 찾지 못해 헤맴                                     시간 절약 - 필요한 API를 미리 파악
      잦은 재작업 - 설계 변경으로 처음부터 다시 작성
      예상치 못한 제약 - 개발 후반부에 불가능한 기능 발견                                  🛡 위험 감소 - 불가능한 기능 사전 발견
                                                                           품질 향상 - 체계적 구조로 깨끗한 코드

2단계: 기능 분해 Step 2

큰 문제를 작은 단위로 나누기 (Decomposition)

Decomposition이란?

복잡한 기능을 한 번에 구현하려 하지 말고, 작은 단계로 분해합니다. 각 단계는 하나의 명확한 작업을 수행하며, 순차적으로 실행됩니
다.

예시: "Room에 번호 자동 부여" → 5단계로 분해                                                   FilteredElementCollector
                                                                                     LocationPoint.Point.X
    1 현재 View의 모든 Room 가져오기                                                                   LINQ ThenBy()
    2 Room을 X 좌표 기준으로 정렬                                                                      Room.Number
    3 Y 좌표로 2차 정렬 (같은 X일 때)                                                                       Transaction
    4 각 Room의 Number에 순번 할당
    5 Transaction으로 변경사항 저장

[Transaction(TransactionMode.Manual)]
public class RoomNumberingPrototype : IExternalCommand
{
// 1. 모든 Room 가져오기
FilteredElementCollector collector = new FilteredElementCollector(doc);
List<Room> rooms = collector.OfCategory(BuiltInCategory.OST_Rooms)
.Cast<Room>().ToList();

// 2. X 좌표로 정렬
var sorted = rooms.OrderBy(r => ((LocationPoint)r.Location).Point.X);

// 3. 번호 부여
using (Transaction t = new Transaction(doc, "Room 번호"))
{ t.Start(); /* 번호 할당 */ t.Commit(); }
}
